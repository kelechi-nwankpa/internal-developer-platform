# portal/ — Backstage developer portal

**Contents:** The [Backstage](https://backstage.io) app, its plugins, and its supporting configuration.

## What lives here

- The Backstage app skeleton (created via `npx @backstage/create-app`).
- Custom Backstage plugins developed for this project.
- Backstage config (`app-config.yaml`, `app-config.production.yaml`) — with **no secrets** ever, only references resolved from AWS Secrets Manager via [`External Secrets Operator`](../platform/README.md).
- Backstage's Software Catalog seeds — links to component YAMLs generated by scaffolder templates.
- Integrations: GitHub OAuth, Kubernetes plugin, ArgoCD plugin, TechDocs, Scaffolder, Search.

## Why this is its own directory

Backstage is a **frontend product** — a React SPA + Node.js backend — and its lifecycle differs from Kubernetes manifests. It has:

- Its own Yarn workspace and build system.
- Its own dependency management (a Backstage version, not a K8s version).
- Its own release cadence, unrelated to platform upgrades.

Keeping it isolated means a Backstage upgrade is a bounded change that doesn't touch the runtime or infra directories.

## Local workflow

Backstage runs on the developer's laptop first, then gets containerised and deployed via GitOps in later phases:

```bash
cd portal
yarn install
yarn dev             # spins up backend on :7007 and frontend on :3000
```

The `Makefile` will expose `make portal-run` as a shortcut once Phase 5 lands.

## Security notes

- **GitHub OAuth** is the only login method. No local users.
- **All plugin permissions** are configured deny-by-default with explicit allows per entity — [CLAUDE.md §4](../CLAUDE.md).
- **No secrets in `app-config.yaml`** — everything is a reference to Secrets Manager, materialised at pod startup via ESO.

## Relates to

- `templates/` — scaffolder templates lives here logically but is separated so it can be extended without touching the Backstage app itself.
- `platform/` — Backstage's K8s and ArgoCD plugins integrate with the components deployed here.
- `docs/adr/` — plugin choices, auth choices, and catalog structure decisions.
